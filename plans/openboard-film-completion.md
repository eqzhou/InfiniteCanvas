# OpenBoard 影视制片闭环补齐计划

## 目标

在不复制任何上游源码、素材、文案或视觉表达的前提下，把现有 Film MVP 补齐为可验收的生产闭环。完成标准不是“存在类型或接口”，而是用户能够在真实 PostgreSQL、画布、GenerationJob、对象存储和 FFmpeg 路径上完成端到端操作，并能恢复、审计和复现。

## 不变量

- 旧自由画布、v1/v2 项目包和现有生成任务行为保持不变。
- 所有写操作按租户授权，使用乐观锁；高权限 Agent 操作必须经过现有确认边界。
- 影视实体仍以服务端为事实来源；画布仅保存可恢复的投影及用户自建内容。
- 生成任务冻结提示词、身份、风格、输入、Provider、模型、参数和成本信息。
- 不读取或使用 DramaClaw 源码、CSS、素材、提示词、文案或截图。

## 依赖图

`A 领域版本与快照 → B 真实画布投影 → C 制作主链 → D 质量与修复 → E 异步交付 → F Agent → G 发布验证`

其中 B 的 UI 与 C 的服务端任务可在 A 完成后并行；D 依赖 A/C，E 依赖 C，F 依赖 D/E。

## A. 领域版本、身份与生成快照

任务：

- 将 Film 文档升级到向后兼容的新版本，增加首帧阶段、对白/旁白结构、不可变资产版本和生成快照。
- 明确角色基础身份、身份变体、默认/候选媒体、声线、适用分集/场景/镜头和项目风格圣经。
- 每个任务保存最终提示词、资产版本快照、输入媒体、Provider、模型、参数、预计/实际成本和产物版本。
- 增加 PostgreSQL 可查询的影视实体投影表，并在 Film CAS 事务中同步；JSON 聚合保留为原子恢复载体，查询事实可由结构表验证。

验证：旧 Film 文档迁移测试、快照不可变测试、租户隔离、CAS 回滚和 PostgreSQL 集成测试。

## B. 主线与画布真实双向投影

任务：

- 将投影刷新接入 `useBoardStore` 和持久化，而不是只显示服务端表单。
- 为集、场景、镜头、角色身份和风格生成稳定受管节点；刷新保留用户节点和布局，失效投影归档。
- 提交前生成白名单字段差异并检查实体修订。
- 为候选图片、视频和音频增加“采用到镜头”“设为身份参考”“设为场景/风格参考”动作。
- 回填保存来源节点、GenerationJob、Provider、模型、提示词、媒体完整性和目标修订。

验证：store 单元测试、刷新/归档/冲突测试、真实持久化测试和 Playwright 画布往返测试。

## C. 完整制作主链

任务：

- 将故事拆解与分集剧本区分；保留确定性解析作为无 Provider 降级路径。
- 增加首帧阶段及独立产物，视频阶段可引用首帧/尾帧。
- 增加对白/旁白条目和角色声线解析，音频任务按条目生成并可汇总到镜头。
- 补齐角色、地点、道具、身份和风格资产草稿生成/审核，以及失败子任务单独重跑。
- 保持每阶段 `draft → running → needs_review → approved` 和依赖闸门。

验证：状态机、父子任务、幂等、取消/恢复、额度、版本失效和 Provider 故障测试。

## D. 质量门禁与版本化修复

任务：

- 增加 FFprobe 媒体完整性、真实时长/画幅、时间线冲突和字幕安全区检查。
- 增加身份/服装/风格/场景连续性规则；视觉语义检查作为可选 AI 规则并明确标识推断。
- 修复提案记录影响范围、预计任务数、预计费用和目标版本。
- 应用修复创建新实体/媒体版本，旧版本可查看和恢复，不静默覆盖。

验证：规则单测、损坏媒体、费用估算、审批、冲突、恢复和审计测试。

## E. 异步时间线交付

任务：

- 将 MP4、SRT、manifest 和素材包统一成持久化导出任务，支持状态、取消、恢复、幂等和失败重试。
- 时间线素材改为可选择的授权媒体，不要求用户手填 storage key。
- manifest 固定引用镜头、任务、身份、风格和媒体版本。
- 保留 FFmpeg 参数数组、隔离目录、并发/时长/输入限制和安全清理。

验证：编译参数、取消/重启、导出版本冻结、下载完整性和容器 FFmpeg 冒烟。

## F. 受控制片 Agent

任务：

- 保留只读 `status/list/check/proposals`。
- 增加下一步建议和交付完整性总结。
- 增加 `approve_stage`、`apply_repair` 和 `export`，声明破坏性/开放世界注解并复用现有用户确认、权限和审计机制。
- Agent 不直接写数据库，全部调用同一领域服务/API。

验证：MCP schema、只读提示、确认拒绝、跨租户、版本冲突和审计测试。

## G. 发布门禁

任务：

- 更新行为规格、功能矩阵、备份格式和运维说明，删除无法由生产路径证明的 `[verified]` 声明。
- 运行 TypeScript、前后端单测、覆盖率、Go race/vet、生产构建、Film E2E、清洁室、安全、依赖、容器与 PM2 检查。
- 在隔离部署中执行 PostgreSQL、对象存储、FFmpeg 和重启恢复冒烟，不影响同机正式服务。

完成条件：六项能力均有生产调用路径、失败路径和自动化证据；不存在仅被单元测试调用而未接入产品的核心实现。

## 完成记录（2026-08-09）

- A 已完成：Film 拓扑兼容迁移、首帧/对白/身份版本、不可变生成快照及 PostgreSQL `openboard_film_entities` 事务投影已接入。
- B 已完成：真实 BoardProject 投影、受管节点刷新/归档、白名单 CAS 回写和带来源审计的媒体采用已接入工作台。
- C 已完成：拆解、剧本、分镜、首帧、声音、视频、合成、交付闸门，以及持久 GenerationJob、取消、恢复和最新任务重试保护已接入。
- D 已完成：媒体完整性、时长/画幅、字幕、身份/风格连续性检查，修复费用预估、版本归档与恢复已接入。
- E 已完成：MP4、SRT、manifest、资产包均通过可恢复 `export` GenerationJob 异步执行，支持取消、幂等、失败重试和授权素材选择。
- F 已完成：只读状态/检查/建议和受确认保护的审批、修复、导出工具已注册到 Agent/MCP，并复用领域 API 与权限边界。
- G 本地门禁已完成：Go test/race/vet、848 个 Web 单测、80% 覆盖率、TypeScript、生产/PM2 构建、脚本/清洁室/许可证/OSV 审计及 Chromium、Firefox、WebKit、移动端 Film E2E 均通过。PostgreSQL 实库测试在缺少 `OPENBOARD_TEST_DATABASE_URL` 的本机跳过，并被配置为 CI 中缺失即失败；远端部署不在本次本地实现范围内。

## 回滚策略

- 所有数据库变更仅向前增加，`film_mode` 可隐藏新入口，不删除影视数据。
- Film 文档读取保持旧版本迁移；写入失败不提升版本。
- 画布投影只操作带稳定管理键的节点，回滚时保留用户节点。
- 新异步导出可关闭能力开关，旧同步交付物仍可下载。
