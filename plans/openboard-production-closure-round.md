# OpenBoard 生产闭环补齐实施计划

## 目标

在不改变现有画布项目行为、不引入第二套队列或不可信能力猜测的前提下，补齐三参考线复审中确认的生产缺口：媒体模型能力目录、影视阶段任务聚合、审核后修复重生成、Film Agent 执行闭环、统一任务中心和正式端到端验证。DramaClaw 的故事图谱等深度能力作为本轮最后一个增量里程碑，建立可持续扩展的数据契约，不复制上游源码、提示词、素材、文案或视觉表达。

## 用户旅程

1. 管理员只能为渠道已启用的模型配置图片、视频或音频能力；未配置且没有本地精确契约的模型不会出现在生成入口。
2. 制片人批量运行镜头阶段后，可以看到一个持久阶段父任务及其镜头子任务、聚合进度、失败数量、费用和重试状态。
3. 制片人批准缺失或损坏媒体的修复提案后，系统保存旧镜头版本，并以明确的生成配置创建新一轮镜头任务；任务创建失败时不得伪装为已修复。
4. Agent 运行拆解或剧本阶段时，必须进入与工作台相同的 AI GenerationJob/candidate 审核链，而不是只修改阶段状态。
5. 用户在统一任务中心查看画布、图片/视频工作台、Film 阶段、镜头和导出任务，并可进入来源页面处理失败任务。
6. 正式 Playwright 使用本地假 Provider 和真实 OpenBoard API 完成 Film 生成、同步、修复、时间线与交付，不 mock Film 领域接口。

## 里程碑与 TDD 验收

### M1：精确媒体能力目录

- RED：未知模型不得获得默认图生图/图生视频能力；无效模型、模式、尺寸、时长和引用限制被拒绝；跨渠道模型配置被拒绝。
- GREEN：渠道配置保存版本化能力条目；精确内置契约可自动派生，管理员覆盖必须受白名单校验；目录响应不含凭据。
- 前端：共享渠道管理提供结构化能力编辑，Film 与工作台只消费目录返回值。

### M2：持久阶段父任务与统一任务中心

- RED：批量任务必须生成一个稳定父任务；子任务必须绑定父任务；同步后父任务聚合 queued/running/needs_review/failed/canceled 状态和进度。
- GREEN：父子关系保存在 Film 文档，API 不再使用客户端合成父任务；统一任务中心展示普通 GenerationJob 与 Film 层级。

### M3：版本化修复重生成

- RED：需要生成的提案没有显式配置时拒绝执行；批准后旧镜头版本保留并创建新任务；重复幂等键不重复扣费或建任务；失败不能标记 `AppliedAt`。
- GREEN：修复执行复用既有 Film 生成、额度、对象存储、取消和恢复边界。

### M4：Film Agent 执行闭环

- RED：`film.run_stage` 对 `decompose`/`script` 必须创建 text GenerationJob；缺少模型、目标集或幂等键时 fail-closed。
- GREEN：Agent 与工作台使用同一阶段运行 API；影视工作台提供可操作的安全 Agent 快捷入口和清晰的确认提示。

### M5：正式 E2E 与恢复证明

- RED/GREEN：增加不 mock `/api/film/**` 的正式测试，使用受控假 Provider 验证 AI candidate、媒体任务、失败镜头重试、修复、时间线冲突、FFmpeg/manifest 导出及浏览器刷新恢复。

### M6：制片深度增量

- 为 AI 拆解契约增加可查询的角色关系、叙事节拍和分集叙事弧，严格校验悬空引用和规模限制。
- 剧本任务增加 `adaptive`、`literal`、`shooting` 三种冻结模式。
- 对白增加可选情绪字段并进入音频提示快照；保持 Provider 不支持时显式降级。
- 风格自动提取、图像池选优作为独立生成操作接入现有任务系统；若本轮没有可验证 Provider 契约，保留为 unsupported，不伪造成功。

## 质量门槛

- 每个里程碑执行 RED → GREEN → 重构，并运行对应 Go/Bun 测试。
- 最终通过 Web 覆盖率、TypeScript、生产构建、Go test/race/vet、关键 Playwright、clean-room、依赖安全检查。
- 所有新增请求均限制大小、拒绝未知字段、验证租户/项目/修订/幂等键；不输出渠道密钥或 Provider 原始敏感错误。

## 发布与回滚

- 数据字段全部向前兼容，旧 Film 文档读取时补空父任务/关系字段，不破坏旧任务。
- 能力目录缺失时关闭对应共享生成入口，已有精确内置契约继续可用。
- 新任务中心和 Agent 快捷入口可独立隐藏；关闭入口不删除任务、媒体或影视版本。

## 实施状态（2026-08-11）

- M1 已完成：共享渠道采用显式或精确内置媒体契约，执行端校验模式、尺寸、画幅、清晰度、完整时长集合和引用数量；管理端支持逐模型配置。
- M2 已完成：Film 阶段父任务与镜头子任务持久化，支持聚合、同步、级联取消、失败镜头重试，并接入统一任务中心。
- M3 已完成：生成型修复使用请求摘要幂等、预计费用校验、事务扣费和不可变镜头版本；失败不伪装成已应用。
- M4 已完成：拆解与剧本 AI 模式创建真实 text GenerationJob 和候选审核记录；高影响 Agent 工具使用一次性、短时、作用域绑定的确认令牌。
- M5 已完成：正式 E2E 不 mock Film API，覆盖失败修复、AI candidate、任务恢复、时间线冲突、交付、画布媒体、Agent、导演台和工作流，共 9 条通过。
- M6 已完成：故事关系、叙事节拍、角色弧、剧本冻结模式和对白情绪进入结构化契约与生成快照；无可验证 Provider 契约的自动风格提取/图像池选优保持 unsupported。
