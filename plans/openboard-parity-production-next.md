# OpenBoard 三参考线生产能力补齐计划

## 1. 目标与边界

在保持 OpenBoard 独立产品架构、品牌和 clean-room 流程的前提下，吸收三条公开参考线中仍有价值的行为：

- Basket Infinite Canvas：画布与 Agent 的高频创作体验。
- Tiger Infinite Canvas：工作台、媒体能力和精确模型契约。
- DramaClaw：从原稿到交付的影视制片深度。

本计划不复制任何上游源码、CSS、素材、提示词、文案、图标或视觉表达。实现依据仅限公开文档、发布说明、可观察行为以及 OpenBoard 自己的产品约束。

本轮“完成”要求每个能力同时具备：真实产品入口、持久化事实、权限/版本边界、失败路径、自动化测试和用户文档。只有类型、静态页面、未接入任务执行器的按钮或仅由测试调用的帮助函数不算完成。

## 2. 用户旅程

1. 作为制片人，我导入原稿后可以先预览识别出的章节、场景和异常，再选择确定性拆解或 AI 拆解，生成可审核的故事摘要、人物、场景、分集和镜头草稿。
2. 作为编剧，我可以对已批准的故事结构运行 AI 分集剧本生成，按集或场景重试失败任务，并在审批前查看冻结的模型、提示词、输入版本和预计费用。
3. 作为导演，我可以把影视场景和镜头发送到 Director，保存场景、机位、角色站位和截图版本，再把正式构图采用为对应镜头的分镜或首帧。
4. 作为剪辑人员，我可以在可视化五轨时间线上拖动片段、调整长度和顺序，看到时间刻度、播放头和素材摘要，并保存到既有乐观锁时间线与 FFmpeg 导出链。
5. 作为管理员，我可以维护一个服务端媒体模型能力目录；前端、校验、任务快照和计费使用同一版本，未知模型继续 fail-closed。
6. 作为画布用户，我可以放大编辑长提示词、对多图结果逐项处理、使用明确的选择/移动工具，并在 Agent 输入框通过 `/` 选择 Skill、通过 `@` 引用当前画布素材。

## 3. 实施里程碑

### M1：AI 故事拆解与剧本生成

- 原稿导入增加预检结果：章节、场景、警告和规范化文本摘要；预检不写入影视事实。
- `decompose` 和 `script` 纳入持久 GenerationJob，使用现有文本 Provider、共享渠道、配额、幂等、取消、租户隔离和恢复机制。
- Film 修订 CAS、GenerationJob、额度预留和算力预留在同一数据库事务提交；任一步失败整体回滚，不依赖请求层补偿删除。
- AI 输出使用有版本的严格 JSON 契约；拒绝未知字段、重复/悬空 ID、超限实体、无效修订和非完整结果。
- 确定性解析继续作为显式降级模式，不把 Provider 失败静默改写为成功。
- 成功结果先保存为不可变 candidate 并进入 `needs_review`，不直接覆盖正式实体；用户查看差异并确认后，才以来源和目标 revision CAS 写入新的影视文档修订。
- 原稿或目标实体在任务执行期间发生变化时，candidate 标记为 `stale`；拒绝或过期 candidate 不改变正式实体，旧版本继续可恢复。
- 前端提供模式、范围、Provider/模型、预览、任务状态和重试入口。

### M2：Film 与 Director 正式来源链

- 为影视场景/镜头增加服务端正式 Director 场景版本绑定，包括 Director 项目节点、场景修订、相机、角色站位、环境、截图摘要和对象版本。
- 影视投影可创建或定位 Director 节点，但不覆盖用户自建 Director 内容。
- Director 正式镜头采用必须由服务端读取 capture，校验同租户同项目、真实 Director 节点、目标镜头修订、PNG MIME/尺寸/SHA-256 和素材归属；客户端不得提交可信 snapshot 或 storageKey。
- 已采用截图复制到稳定的 Film 媒体命名空间；普通 capture 删除不得破坏历史镜头，绑定失败时清理复制对象并由孤儿媒体任务兜底。
- 生成快照、质量检查、manifest 和恢复包包含 Director 来源版本。

### M3：可视化制片时间线

- 保留现有五轨和表单精确编辑，增加时间刻度、播放头、轨道画布、片段拖动/缩放、吸附和键盘微调。
- 所有交互通过纯函数产生不可变时间线草稿；拖动结束才形成一次历史/保存动作。
- 字幕、视频和音频片段显示不同摘要；未知时长和损坏媒体明确告警。
- 移动端降级为可横向滚动的轨道视图，不提供难以可靠操作的精细拖拽。

### M4：统一媒体模型能力目录

- 服务端提供按租户可见的版本化图片/视频/音频能力目录，记录协议、模型族、生成模式、尺寸、时长和参考素材限制。
- 管理端只能从已启用渠道模型中选择并配置；敏感凭据不进入目录响应。
- 生成请求、费用预估、任务快照和恢复都冻结目录版本及解析后的生成模式。
- 前端从目录派生选项；目录不可用时只保留已有精确静态契约，不猜测未知能力。
- ComfyUI、MiMo、Seedance 2.5 等只有在取得独立可核验的官方契约后接入；否则保持 unsupported。

### M5：Basket/Tiger 高价值交互

- 长提示词弹窗编辑并与节点草稿实时同步。
- 多图结果支持主图、展开/收起、单项下载、创建副本、删除以及失败项重试。
- 画布增加持久选择/移动工具，空格或 Control 临时反转且不干扰输入控件。
- Agent composer 增加 `/Skill` 和 `@画布素材` 建议菜单，选择内容作为结构化元数据持久化并在历史恢复。
- 设置页展示站点生成额度和服务端可确认的媒体占用；无法可靠取得的浏览器/对象仓库容量不伪造。

## 4. 明确后置项

- 全站中英文国际化：独立产品项目，避免本轮同时重写全部文案。
- WebDAV 媒体后端：需要 SSRF、原子写、配额、Range、凭据轮换和大文件恢复设计；现有 WebDAV 继续只用于备份。
- 桌面客户端：现有 PWA/浏览器/PM2/Compose 路径优先，除非出现明确离线桌面需求。
- OCR、专业 NLE 关键帧/蒙版/复杂特效和本地模型安装器继续不在本轮范围。

## 5. TDD 映射

| 里程碑 | RED 测试目标 | GREEN 验收 |
|---|---|---|
| M1 | Go 领域/HTTP 集成测试；并发幂等、事务回滚、租约、退款、stale 和恶意 JSON；Film client/component 单测；Film Playwright | AI 结构任务真实排队、恢复、校验、candidate 审核；确定性降级显式可选且无孤儿任务 |
| M2 | Film/Director 绑定领域测试、伪造节点/跨租户/修订冲突/capture 删除测试、画布往返 E2E | Director 来源进入镜头事实、快照、检查和 manifest，历史媒体不依赖临时 capture |
| M3 | 时间轴几何纯函数测试、组件键盘/指针测试、桌面与移动 E2E | 拖动、裁剪、吸附、保存冲突和导出保持一致 |
| M4 | Go 目录校验/API/权限测试、前端派生测试、生成快照集成测试 | UI、校验、费用和任务使用同一冻结能力版本 |
| M5 | 组件单测、store 测试、Agent 元数据恢复测试、跨浏览器 E2E | 所有高频操作可访问、可恢复、无画布溢出或快捷键冲突 |

每个里程碑执行：测试先行并确认 RED → 最小实现并确认 GREEN → 重构 → 局部覆盖率 → checkpoint commit。全部完成后运行 Web 覆盖率、Go test/race/vet、TypeScript、生产构建、Playwright、clean-room、许可证、OSV、容器和 PM2 验证。

## 6. 发布与回滚

- 所有数据变更向前兼容；旧 Film 文档迁移时不丢失已有媒体和审批状态。
- 新能力使用已有 `film_mode` 和细分 capability gate；目录或 Provider 不可用时只关闭对应生成入口。
- 发布前备份 PostgreSQL、媒体对象清单和 master key；不得把 Redis 或不含凭据的 WebDAV 包当作完整备份。
- 关闭新入口不得删除任务、Director 来源、时间线或影视版本数据。
